# v1.0.33 — what changed, and why

One user request in two acts, delivered on a single branch
([PR #92](https://github.com/devfassaf/kids_player/pull/92)): **the add tab searches
YouTube** — type like on youtube.com, see YouTube's own results, preview, add — and
**a channel/playlist result opens for browsing**, so the parent can inspect a source's
actual content before deciding between one video and the whole catalogue. A full
self-review pass ran over everything before merge; its findings (one HIGH) are fixed
and pinned below. The detail lives in [CLAUDE.md](../CLAUDE.md); this is the map.
For how to verify any of it, see [TESTING.md](TESTING.md). Previous release records:
[V1032.md](V1032.md), [V1026.md](V1026.md), [V1025.md](V1025.md).

## 1 · The search (keyless, quota-free)

The official `search.list` costs 100 units per call on a key every family shares —
~80 searches a day would freeze sync for everyone — so it stays BANNED. The mechanism
is the KEYLESS youtubei endpoint that feeds youtube.com's own results page: 0 quota,
no API key, no login, verified live including the native layer's Dalvik UA (an API,
not a page — the v1.0.32 mobile-redirect trap does not apply).

- **One-module blast radius**: ANY `youtubei/` literal may exist only in
  [ytsearch.js](../www/js/ytsearch.js) (guard-pinned; the endpoint constants are
  deliberately NOT exported). No key ever reaches it — `key=` in a URL, a
  `getApiKey()` call and a keys import all fail the suite.
- **No Shorts anywhere** (the user's decision): reel shelves are dropped wholesale, a
  videoRenderer with the SHORTS overlay / a `/shorts/` navigation / a
  `reelWatchEndpoint` is dropped, and `RD…` mixes (endless auto-radios — not
  importable lists) are dropped. Each filter is pinned by a planted fixture in which
  the forbidden item sits between two survivors.
- **The parsers are TOTAL**: innertube's array→keyed-object churn returns
  "unrecognized", never a throw (review-caught — a throw used to surface as "בדקו את
  החיבור" over working Wi-Fi, hiding the real alarm).
- **Two distinct failure messages** (the v1.0.27 rule): 'network' = try again, the
  shown results stay; 'parse' = "YouTube changed something", the update-the-app alarm.
  A 200-with-HTML interstitial maps to 'network' on BOTH transports (review-caught:
  device and browser used to disagree).
- **Suggestions**: the keyless suggest endpoint with `oe=utf-8` — LOAD-BEARING, without
  it Hebrew answers arrive in windows-1255 and the dropdown renders ���� (measured).
  Taps bind on pointerdown (click loses the race against the input's blur) AND click
  (a TV remote's OK produces no pointerdown), latched against double-fire.
- **Two monotonic seq counters** (search vs suggestions): a late response never paints
  a newer query's list; hiding the dropdown invalidates its in-flight fetch.

## 2 · One add path

`addClassifiedRow` was cut out of `parentAdd` (the v1.0.25 lesson: two callers with
private copies of "add" is how flows drift). A search result is normalized to a
canonical URL and RE-CLASSIFIED through `classifySourceRow` — classifyLink stays THE
safety boundary, and a kind mismatch is refused. A video goes live immediately with
the result's own title (no oEmbed fetch); a channel/playlist runs the familiar
import-then-ask flow. Exactly two callers, guard-pinned. share.js stays separate on
purpose: pending-first is a different curation policy.

"✓ קיים" is precomputed against BOTH scopes through the same `libraryHasVideo` helper
the add itself uses — the row must agree with what the add would answer.

## 3 · Browsing inside a result

A channel shows **its Videos tab only** (`youtubei/v1/browse` + the tab's own protobuf
params) — Shorts live in a separate tab, so what the parent browses is by construction
what a subscription would import. A playlist shows its contents (`VL`-prefixed
browseId). The header carries back / avatar / name / one ➕ for the whole source; every
video row behaves exactly like a search result. Back — the button and hardware back,
gated on the add panel being visible — restores the search results untouched. ONE
state map serves both lists: a ✓ earned inside the browse shows on the results row and
vice versa (a video key is global).

**An unparsable CONTINUATION is end-of-list, never the 'parse' alarm** — measured: a
playlist delivered whole on page one still carries a token whose continuation answers
nothing but trackingParams. Only a first page may raise the alarm.

## 4 · The review pass (what it caught)

All findings demonstrated against the running code, all fixed on the branch, each with
a test or a proven guard:

1. **HIGH — ghost browse rows**: submitting a search from inside a browse tore the
   browse down by hand instead of through `closeYtsBrowse`, leaving the OLD browse
   rows rendered and tappable while the fetch ran — and forever when it failed. A
   thumbnail tap then previewed the WRONG video. Fixed: one teardown path.
2. **previewDecide re-entrancy**: a double-tap on ➕ ran two decisions on the same
   mutated context — the second splice silently skipped a video the parent never saw.
   Now latched (`previewDeciding`), covering all four bubble buttons.
3. **Parser totality** (above) + **interstitial mapping** (above).
4. **Suggestion races**: an in-flight fetch re-opened a dismissed dropdown (hide now
   bumps the seq); a TV remote couldn't pick a suggestion (click handler added);
   arrowing into the dropdown no longer destroys it (blur checks focus target).
5. **Profile switch kept the previous child's search area**: stale "✓ קיים" marks
   computed against the other child's scopes. `resetYtsUi()` on activation — the same
   profile-identity rule as the buildFolders cache key.
6. **Cross-surface double-add**: the browse-head ➕ and the result row could run two
   concurrent imports of the same source. A shared transient `'adding'` state (drawn
   as ⏳) is the cross-surface latch.
7. **Unvalidated playlist ids**: a hostile id containing `"]` flowed into a
   querySelector string. `PLAYLIST_ID` now validates like every other id class.
8. **Bubble button matrix extracted pure** (`playerlogic.previewBubbleButtons`,
   node-tested per mode, unknown mode fails safe) — the hand-ordered toggles were
   where the "live 🗑️ over a search result" bug had to be hand-avoided.

Also: the dev proxy's over-cap 413 never reached the client (destroying the request
socket killed the response too); dead `searchMessage` stages deleted; endpoint
constants unexported (an exported constant plus a hand-appended key parameter would
have tripped no guard).

**A guard was caught being vacuous by its own red-check**: the kind-mismatch pin
matched a bare substring that a `false &&` plant kept alive. It now pins the full
conditional shape. Every new guard in this release was proven to fail on a planted
regression before it was trusted.
