## 1 · Time labels (like the YouTube app)

Pure `playerlogic.formatTime`: floored seconds, `h:mm:ss` above an hour, `0:00` for
NaN/Infinity/negative — `getDuration()` answers 0 before metadata and Infinity for a live
stream, and none of those may reach the child's screen. The labels live INSIDE
`.player-hud`, so they inherit the containers' permanent `pointer-events:none` (the
HUD-bar invariant) and fade with the HUD.

## 2 · Resume playback

OFF by default (user's decision — a family that never opens settings keeps start-from-zero
exactly). The **setting** syncs (`resume`, safe-on-tie false); the **position** is
device-local: it changes every few seconds, and syncing it would rewrite the family's
Drive document on every pause — the `giftRank` lesson, replayed. The decisions are pure
(`resumeStartAt` / `resumeSaveDecision` / `watchedFraction`): resume 3s before the stop
point (user's spec), a stop within 12s of the end clears (or every video sticks at its
tail forever), stops under 8s are ignored so an accidental tap cannot erase progress.

Collateral fix: applying a remote unwrap in `drive.applyRemoteDoc` was a **blind put**
that erased the local record wholesale — it now folds through pure `mergeAppliedState`,
preserving the local position and MIN-merging `unwrappedAt` (the old code also let a later
remote unwrap beat an earlier local one).

## 3 · Screen-off pauses the video

Field report: pressing the power button darkened the screen but the soundtrack kept
playing — Android does not pause the WebView, and the app listened only to the RESUME half
of the lifecycle. `platform.onAppPause` is the missing half; the handler banks the
playhead, then pauses **in place** (never `stop()` — a torn-down player is the reported
"הסרטון נעלם"). When the screen returns the video waits, paused, where it stopped.

## 4 · The sources tab

Subscriptions fold into a closed `<details>` (newest first, by `addedAt`); a channel whose
sync decision nobody has made surfaces above the fold under "ערוצים חדשים" for 24 hours.
The new `decidedAt` field is stamped by the three-way dialog's REAL answers, by the
auto-approve toggle, and at creation for sheet rows carrying an explicit auto/manual flag —
"אחר כך" deliberately stamps nothing, and 24h drains the row regardless (the section cannot
silt up). User's choice: only channels *awaiting configuration* appear; a decision made on
any device travels with the record.

## 5–7 · The simplification wave

- The privacy/terms/what's-new buttons left the About tab. The policies live on the site
  as sticky nav tabs on all three pages — **the URLs must stay alive: Google OAuth
  verification points at them**. What's-new kept its one meaningful surface: the update
  prompt before an install.
- The add form's name/image fields are gone. YouTube content always fetched its own
  title/thumbnail; a direct mp4's display name now derives from the filename in the link
  (pure `classify.titleFromFileUrl`, Hebrew percent-decoding included), its thumbnail from
  the captured first frame (v1.0.5 machinery).
- Backup: the status line and "גיבוי עכשיו" are gone; the block shows **only while backup
  is off** — the enable door for a family that skipped the first-launch connect, without
  which they could never turn it on. Sources: create/join/disconnect are gone;
  the profile-creation wizard (kept — user's choice) is now the ONE place a sheet is
  attached, and `connectSheetUrl` was deleted with its last callers. Both safety surfaces
  stayed: the mirror valve and the sheetwrite queue warnings.

## 8 · @BARDAK613, third recurrence — the mobile page

Why v1.0.29–31 kept passing verification and failing on the tablet: a request carrying a
MOBILE user-agent (the WebView's, or the native HTTP layer's Dalvik default) is
**redirected to m.youtube.com**, whose page has NO `externalId` and NO canonical link while
carrying FIVE decoy `"channelId"` occurrences (measured live). The anchored extractor
correctly refused → fell back to the poisoned cache → the decoy (genuinely empty) channel.
Every earlier fix was verified in a desktop browser, which gets the www page.

The mobile page names its identity in its own anchored shapes — the RSS alternate link
(`feeds/videos.xml?channel_id=UC…`) and the og:url/twitter:url metas pointing at
`/channel/UC…` — both now matched, before the decoy-prone legacy key. Verified live across
the UA matrix and generalized on two more channels. Devices self-heal: the sheet row keeps
the @handle and re-resolves every sync. **The lesson, now in TESTING.md: probe scrape
fixes against the MOBILE page variant.**

## 9 · Picker exit button

User's decisions: always visible; short confirm; the parent code when the kiosk is armed.
The subtle half: on a boot picker no profile is active, but the kiosk was armed from the
LAST ACTIVE one — `askExit` now falls back to the stored profile id, or the button would
have walked straight through an armed lock (the real case: a cold-start share raising the
picker on a locked device). An invariants guard pins both the fallback and the binding,
proven against planted regressions.

## 10 · Channel logos: bytes, not URLs

The avatar was re-fetched from the network on every render, so flaky Wi-Fi — or a rebrand
whose old URL 404s — showed 📺 despite the app having had the picture moments earlier. The
bytes now live in the thumbs store (`logo:<channelId>`, ~30KB, `srcUrl` in the meta) and
render from the device, offline included; a missing logo retries on every home entry
(user's spec). Pure `planLogoCache`: cached bytes always render, the render never waits
for the network, a new URL refreshes in the background.

Three self-review catches, each now pinned:
- **The serve half must never dedupe** (only the network half): a render arriving
  mid-fetch got nothing, and the fetch painted a detached img — measured as 📺 tiles over
  a full cache. `logoTarget` tracks the latest mounted img.
- **A late fetch may not paint into a host that moved on** (`planLogoDelivery`):
  `#folder-logo-top` is one element shared by every folder view, and channel A's slow
  fetch used to plant A's logo into folder B's header.
- **Warm memory paints first** (`logoFirstPaint`): the unconditional `img.src = url` hit
  the network on every render even with a full cache — verified after the fix: zero ggpht
  requests across a whole session.
